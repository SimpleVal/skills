# README.md Guidance

Use `README.md` as the primary human-facing project introduction and onboarding guide.

It should help developers understand:

- what the project does;
- what they need to get started;
- how to set it up and run it;
- the main usage examples;
- where detailed development guidance lives.

## Adaptive template

```md
# <Project name>

<Brief project purpose and scope.>

## Requirements

<Required runtimes, tools, or services.>

## Setup

<Minimal installation and configuration steps.>

## Run

<Primary command or workflow to start the project.>

## Usage

<Main usage examples or common workflows.>

## Development

<Link to relevant development documentation.>
```

Include only sections that add useful information.

## Guidance

- Keep the README focused on human onboarding and primary usage.
- Use only setup, run, and usage instructions supported by repository evidence or confirmed by the user.
- Do not invent commands, environment variables, ports, URLs, or examples.
- Link to architecture, coding standards, and verification guidance instead of duplicating them.
- Preserve useful existing sections and structure when updating an existing README.
- Avoid detailed implementation rules or internal architecture unless they are essential for basic project understanding.
